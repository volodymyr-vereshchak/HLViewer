# Формат файла enterprise_mappings.xlsx

## Описание
Файл содержит маппинг вычислителей предприятий к линиям ГС для вычитания объемов предприятий из суточного тренда.

## Формат файла
**Имя файла:** `enterprise_mappings.xlsx`
**Расположение:** `D:\Projects\HLViewer\HLViewer\backend\data\enterprise_mappings.xlsx`

## Структура колонок

| Колонка | Тип | Обязательная | Описание | Пример значения |
|---------|-----|--------------|----------|-----------------|
| `line_id` | int | ✅ Да | ID линии из таблицы `gas_volume_line` в HLViewer БД | 1 |
| `serNum` | int | ✅ Да | Серийный номер вычислителя (device serial number) | 123456 |
| `mfDev` | int | ✅ Да | Код производителя вычислителя (manufacturer device code) | 16 |
| `typeDev` | int | ✅ Да | Тип устройства (device type code) | 1 |
| `chNum` | int | ✅ Да | Номер канала вычислителя (channel number) | 1 |
| `enterprise_name` | str | ❌ Нет | Название предприятия (для документации) | "ТОВ Завод №1" |
| `active` | bool | ✅ Да | Использовать ли этот маппинг (TRUE/FALSE) | TRUE |

## Обязательные колонки для работы API

**Минимальный набор:**
- `line_id` - для привязки к линии ГС
- `serNum` - для идентификации вычислителя в DPD API
- `mfDev` - для идентификации производителя в DPD API
- `typeDev` - для идентификации типа устройства в DPD API
- `chNum` - для идентификации канала в DPD API
- `active` - для включения/отключения маппинга

**Опциональные колонки:**
- `enterprise_name` - только для удобства чтения, можно опустить

## Минимальный пример (CSV формат)

```csv
line_id,serNum,mfDev,typeDev,chNum,enterprise_name,active
1,123456,16,1,1,ТОВ Завод №1,TRUE
1,123457,16,1,1,ТОВ Завод №2,TRUE
6,234567,16,1,1,ПАТ Підприємство А,TRUE
```

## Пример с отключенным маппингом

```csv
line_id,serNum,mfDev,typeDev,chNum,enterprise_name,active
1,123456,16,1,1,ТОВ Завод №1,TRUE
6,234568,16,1,1,ТОВ Підприємство Б,FALSE
```

В этом примере вычислитель "ТОВ Підприємство Б" (line_id=6) отключен и НЕ будет учитываться при вычитании объемов.

## Значения полей DPD API

### Код производителя (mfDev)
Возможные значения согласно DPD API:
- `1` - РадмирТех (Radmirtech)
- `3` - ГРЕМПІС (GREMPIS)
- `4` - Тандем (Tandem)
- `5` - Укргазтех (Ukrgaztech)
- `11` - 104.UA_SMART
- `16` - (уточнить у администратора DPD)

### Тип устройства (typeDev)
Зависит от производителя. Типичные значения:
- `1` - основной тип
- (другие значения уточнить в DPD API документации)

### Номер канала (chNum)
Обычно `1`, но может быть 0-N в зависимости от конфигурации вычислителя.

## Как заполнить файл

### Шаг 1: Узнать line_id
Выполнить SQL запрос к HLViewer БД:
```sql
SELECT id, line, name FROM gas_volume_line WHERE gas_volume_calc_id IN (
  SELECT id FROM gas_volume_calc WHERE lumg_id = 1
);
```

Или через API:
```bash
curl "http://localhost:8000/lines/?lumg_id=1"
```

### Шаг 2: Узнать параметры вычислителей предприятий
Получить из системы DPD или из CSV файлов проекта `D:\PO\dpd\`:
- `dpd.csv` - промышленные вычислители
- `dpdkvr.csv` - КВР вычислители
- `dpdp.csv` - побутові вычислители

Файлы содержат колонки:
- Серийный номер (serNum)
- Производитель (mfDev)
- Тип устройства (typeDev)
- Канал (chNum)
- Организация (enterprise_name)

### Шаг 3: Сопоставить вычислители с линиями
Определить какие предприятия подключены к каким линиям ГС. Это требует знания топологии сети.

### Шаг 4: Создать Excel файл
1. Открыть Excel или LibreOffice Calc
2. Создать лист с названием "Mappings" (или любое другое)
3. Добавить заголовки в первую строку
4. Заполнить данные
5. Сохранить как `enterprise_mappings.xlsx`

## Тестовый пример для проверки работы

Минимальный файл для тестирования интеграции:

```csv
line_id,serNum,mfDev,typeDev,chNum,enterprise_name,active
1,100000,16,1,1,Тестове підприємство 1,TRUE
```

Этот файл:
- Привязывает 1 вычислитель к line_id=1
- Использует тестовые параметры (serNum=100000)
- Позволит проверить работу endpoint без реальных данных

## Валидация файла

При загрузке файл проходит следующие проверки:

1. **Наличие обязательных колонок:**
   - line_id
   - serNum
   - mfDev
   - typeDev
   - chNum
   - active

2. **Типы данных:**
   - line_id: целое число > 0
   - serNum: целое число
   - mfDev: целое число
   - typeDev: целое число
   - chNum: целое число >= 0
   - active: булево значение (TRUE/FALSE, 1/0, True/False)

3. **Уникальность:**
   - Комбинация (serNum, mfDev, typeDev, chNum) должна быть уникальной
   - Один вычислитель не может быть привязан к нескольким линиям

4. **Ссылочная целостность:**
   - line_id должен существовать в таблице gas_volume_line

## Обработка ошибок

### Файл не найден
```
HTTP 500 Internal Server Error
{
  "error": "Enterprise mappings file not found",
  "path": "backend/data/enterprise_mappings.xlsx"
}
```

**Решение:** Создать файл по указанному пути

### Неверная структура файла
```
HTTP 500 Internal Server Error
{
  "error": "Invalid mappings file structure",
  "details": "Missing required column: line_id"
}
```

**Решение:** Проверить наличие всех обязательных колонок

### Нет активных маппингов
```
HTTP 200 OK
[]
```

**Поведение:** Это норма, если все маппинги отключены (active=FALSE) или нет маппингов для запрошенных line_id

### DPD API вернул ошибку
```
HTTP 503 Service Unavailable
{
  "error": "DPD API unavailable",
  "details": "Connection timeout"
}
```

**Поведение:** Frontend должен показать warning и построить тренд без вычитания предприятий

## Примеры использования

### Пример 1: Одно предприятие на линии
```csv
line_id,serNum,mfDev,typeDev,chNum,active
1,123456,16,1,1,TRUE
```

Результат: Из line_id=1 будет вычитаться объем вычислителя 123456

### Пример 2: Несколько предприятий на одной линии
```csv
line_id,serNum,mfDev,typeDev,chNum,active
6,234567,16,1,1,TRUE
6,234568,16,1,1,TRUE
6,234569,16,1,1,TRUE
```

Результат: Из line_id=6 будет вычитаться сумма объемов трех вычислителей

### Пример 3: Предприятия на разных линиях
```csv
line_id,serNum,mfDev,typeDev,chNum,active
1,123456,16,1,1,TRUE
6,234567,16,1,1,TRUE
10,345678,16,1,1,TRUE
```

Результат: Каждая линия вычитает свои предприятия

### Пример 4: Временное отключение предприятия
```csv
line_id,serNum,mfDev,typeDev,chNum,active
1,123456,16,1,1,FALSE
```

Результат: Вычислитель 123456 игнорируется (не вычитается), можно использовать для отладки

## Обновление файла

После изменения файла:
1. Сохранить файл
2. Подождать до 5 минут (кеш обновляется автоматически)
3. Или перезапустить backend для немедленного обновления

**НЕ требуется** перезапуск frontend - изменения применяются на backend.
