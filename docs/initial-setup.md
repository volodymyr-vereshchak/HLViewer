# HLViewer — Первинне налаштування (після розгортання)

Документ описує **первинне налаштування** системи через **адмін-панель** після того, як ПЗ
розгорнуто на сервері (бекенд, БД і фронтенд підняті, міграції застосовані — див.
[deployment-docker.md](deployment-docker.md)). Усі дії виконуються під обліковим записом
з роллю **admin**.

> Це разові дії з наповнення системи даними. Про щоденну роботу з програмою (перегляд
> архівів, звіти, тренди) — див. [user-guide.md](user-guide.md).

<a name="1-філіали"></a>
## 1. Філіали — вкладка «Філіали»

Перше, що заводимо в системі, — **філіали**. Це верхній рівень ієрархії даних
(**Філіал → ЛУМГ → Обчислювач → Лінія**), на нього спираються всі подальші налаштування.

1. Увійдіть під адміністратором і відкрийте розділ **Адмін** → у меню зліва вкладку **«Філіали»**.
2. Заповніть форму й натисніть **«Додати»**:
   - **Назва** — повна назва філіалу.
   - **Скорочена назва** — коротка (використовується в компактних списках, необов'язково).
3. Повторіть для кожного філіалу, який потрібно завести.

Рядки в таблиці можна редагувати (**«Ред.»**) і видаляти (**«Видалити»**).

<a name="2-користувачі"></a>
## 2. Користувачі — вкладка «Користувачі»

Користувачів заводимо під **обліковим записом адміністратора за замовчуванням** — його логін
і пароль задані при розгортанні у файлі `.env.v2` (змінні `ADMIN_USERNAME` / `ADMIN_PASSWORD`).
Відкрийте розділ **Адмін** → вкладку **«Користувачі»**.

**Кого саме заводити — залежить від режиму входу `AUTO_LOGIN`** (задається у `.env.v2`):

- **`AUTO_LOGIN` увімкнено.** Усі відкривають систему автоматично, без вікна входу, під спільним
  обліковим записом-переглядачем. Окремих переглядачів створювати не треба — заводьте лише
  **адміністраторів** (роль `admin`), тобто тих, хто має право **редагувати дані**.
- **`AUTO_LOGIN` вимкнено.** З'являється вікно входу — заводьте **всіх потрібних користувачів
  з розмежуванням прав**: адміністраторів (`admin`) і переглядачів (`viewer`), кожному —
  доступ до відповідних філіалів.

**Як створити користувача:**

1. У формі вкажіть **Логін**, **Відображуване ім'я**, **Роль** (`viewer` або `admin`).
   Для ролі **viewer** нижче відмітьте **«Доступ до філій»** — до яких філіалів відкрито доступ
   (admin бачить усі філіали). Viewer без відмічених філій бачить **усі** філіали.
2. Натисніть **«Створити»** — система покаже **згенерований пароль** у зеленому банері
   (кнопка «Копіювати»). Збережіть його: потім пароль можна лише скинути, а не подивитися.
3. У таблиці по кожному користувачу доступні:
   - **«Ред.»** — змінити ім'я / роль / доступ до філіалів;
   - **«Новий пароль»** — згенерувати новий пароль;
   - **«Деактив.» / «Активув.»** — тимчасово заблокувати / розблокувати доступ (без видалення);
   - **«Видалити»** — видалити назавжди.

> Систему захищено від блокування самої себе: не можна деактивувати, видалити чи понизити в
> ролі **останнього активного адміністратора**.

<a name="3-лумг"></a>
## 3. ЛУМГ — вкладка «ЛУМГ»

ЛУМГ — другий рівень ієрархії (**Філіал → ЛУМГ → Обчислювач → Лінія**).

> **Трохи контексту.** Родоначальник hostlib-файлів — програмний комплекс **АСК-1**. За його
> архітектурою у межах одного суб'єкта (ЛУМГ / видобутку / тощо) кожен **обчислювач** має
> **унікальну адресу**. Саме тому ЛУМГ (чи інший суміжний суб'єкт ринку) — це та одиниця, у
> межах якої далі заводяться обчислювачі з унікальними адресами.

**Що заводимо.** Усі **ЛУМГ, видобутки та інші суміжні суб'єкти ринку**, які постачають
hostlib-файли. Кожен такий суб'єкт додається як окремий запис ЛУМГ.

1. Відкрийте розділ **Адмін** → вкладку **«ЛУМГ»**.
2. Заповніть форму й натисніть **«Додати»**:
   - **Назва** — назва ЛУМГ / видобутку / суб'єкта.
   - **Філіал** — виберіть філіал (з п.1), якому належить цей ЛУМГ.
3. Повторіть для кожного суб'єкта, що постачає hostlib-файли.

Для зручності перегляду є **фільтр за філіалом**. Рядки редагуються (**«Ред.»**) і видаляються
(**«Видалити»**).

<a name="4-шляхи"></a>
## 4. Шляхи до архівів (АС4) та ЄІС-коди — вкладка «Шляхи даних»

Тепер вказуємо, **звідки система читає hostlib-архіви**, і прив'язуємо **ЄІС-коди** до ЛУМГ.
Відкрийте вкладку **«Шляхи даних»** і вгорі виберіть **Філію** — налаштування показуються для неї.

**Шлях до архівів (по кожному ЛУМГ).** Для кожного ЛУМГ філіалу:

1. **«Додати шлях»** — вкажіть шлях до папки з архівами на змонтованій шарі сервера АС4,
   напр. `/mnt/as4/ZP` (про монтування шари див. [deployment-docker.md](deployment-docker.md), розділ 6).
2. Увімкніть галочку **«Активний»** і збережіть.

**Прив'язка ЄІС-кодів.** У блоці **«ЄІС коди»** (розгортається кнопкою) для ЛУМГ:

- додайте код вручну в поле **«Ввести ЄІС код вручну»** → **«Додати»**; **або**
- натисніть **«🔍 Сканувати архів»** — система просканує папку й запропонує знайдені нові коди
  чекбоксами; відмітьте потрібні й натисніть **«Додати вибрані (n)»**.

> Один ЄІС-код не можна прив'язати до двох ЛУМГ одночасно — система про це попередить.
> Якщо ЄІС-коди не задані, ЛУМГ працює в режимі **«Прямий»** (шлях читається напряму, без
> фільтрації за кодами).

> 🖼️ **Скріншот 4** — _«Шляхи даних»: шлях до архівів ЛУМГ, блок ЄІС-кодів, сканування архіву._
> _(файл: `screenshots/4-paths-eis.png`)_

<a name="5-оновлення"></a>
## 5. Завантаження даних — вкладка «Оновлення»

Після прив'язки ЄІС-кодів запускаємо **завантаження архівних даних**. Саме на цьому кроці
система читає hostlib-файли й **автоматично створює обчислювачі та лінії** за їхніми
унікальними адресами (з розділу 4 — архітектура АСК-1).

1. Відкрийте вкладку **«Оновлення»**.
2. Натисніть **«Оновити всі»** — запуститься завантаження по **всіх ЛУМГ**. Прогрес видно по
   кожному ЛУМГ статусами: **В черзі / Очікує / Виконується / Готово / Помилка**.
3. Кнопка **«Оновити»** в рядку окремого ЛУМГ — оновити лише його.
4. **«Скинути»** — скинути статус, якщо завантаження «зависло».

Після успішного оновлення обчислювачі й лінії з'являться у відповідних вкладках (розділ 6) —
поки що з **технічними іменами, згенерованими за адресами**. Оскільки в бінарних архівах
зберігаються лише номери (адреси), а не назви, система підставляє їх як тимчасові імена:

- **Обчислювач** отримує ім'я виду **`a<адреса>`** — літера `a` + адреса приладу
  (напр. обчислювач з адресою `5` → `a5`, з адресою `12` → `a12`).
- **Лінія** отримує ім'я виду **`l<номер>`** — літера `l` + номер лінії
  (напр. лінія `1` → `l1`, лінія `2` → `l2`).

Це робочі, але незрозумілі для людини назви — у розділі 6 присвоюємо їм нормальні імена
(через `ask.cfg` або вручну).

<a name="6-обчислювачі"></a>
## 6. Обчислювачі та лінії

Після завантаження даних (розділ 5) обчислювачі й лінії вже **створені** — їх залишається
**назвати й донастроїти**. Це можна зробити двома способами.

### 6.1 Варіант 1 — імена з `ask.cfg`

Швидкий спосіб, якщо є конфіг АСК: імена ЛУМГ / обчислювачів / ліній беруться з файлу
`ask.cfg` (або `askroc.cfg`).

1. Підготуйте `ask.cfg` у структурі **ЛУМГ → Обчислювач → Лінії** (як на скріншоті).
2. Скопіюйте файл у проєкт за шляхом
   `backend/data/askcfgs/СКОРОЧЕННЯ_ФІЛІЇ/ask.CFG`.
   > У Docker репозиторій змонтовано в контейнер (`.:/app`), тож файл, покладений у цей шлях
   > на хості, автоматично буде видно всередині контейнера — окремо «прокидати» його не треба.
3. У вкладці **«Шляхи даних»** (блок **«Конфіг імен (ASK.CFG)»** на рівні філіалу) натисніть
   **«Додати шлях»** і вкажіть шлях до скопійованого конфіга; увімкніть **«Активний»**, збережіть.
4. Натисніть **«Переглянути CFG»** — з'явиться таблиця ЛУМГ із конфіга (**ЛУМГ в CFG (gis_name)**,
   кількість приладів і ліній).
5. У колонці **«ЛУМГ в БД»** зіставте кожен ЛУМГ із конфіга з **ЛУМГ, доданим у розділі 3**,
   і натисніть **«Зберегти маппінг»**.
6. Натисніть **«Оновити імена»** — імена з конфіга застосуються до наявних обчислювачів і ліній.

> _(файл: `screenshots/6-1a-askcfg-format.png`)_

> _(файл: `screenshots/6-1b-cfg-mapping.png`)_

### 6.2 Варіант 2 — вручну

Якщо конфіга немає, редагуємо обчислювачі й лінії, що **з'явилися після оновлення**, вручну.

**Обчислювачі — вкладка «Обчислювачі».** Угорі виберіть **Філію** і **ЛУМГ**. Для кожного
обчислювача через **«Ред.»** задайте зрозумілу **Назву** та **Тип** (з довідника типів);
за потреби скоригуйте **Адресу** і **c_time**. Новий обчислювач можна додати кнопкою
**«+ Додати обчислювач»**.

**Лінії — вкладка «Конфігурація».** Угорі виберіть **Філію** і **ЛУМГ**. По кожній лінії
задайте **Назву**, **№ лінії**, прив'язку до **Обчислювача**, перемикач **Лічильник**, а також:
- **В звіт** — включати лінію у звіти;
- **В тренди** — включати у тренди;
- **Вис. тиск** — лінія високого тиску;
- **Тиск, од.** / **Перепад, од.** — одиниці вимірювання.

<a name="7-промисловість"></a>
## 7. DPD-креденшали та промисловість

Промисловість — це об'єми підприємств, які система отримує з **DPD API**. Спочатку налаштовуємо
доступ до API, потім завантажуємо перелік підприємств.

### 7.1 DPD-креденшали — вкладка «DPD Креденшали»

Доступ до DPD API налаштовується **окремо для кожного філіалу**. Виберіть філіал, натисніть
**«Додати»** і заповніть поля (як на скріншоті):

- **API Base URL** — базовий URL API промисловості (напр. `https://rest-direct.КОД_ФИЛИИ.iot.grmu.com.ua/api/v1`).
- **Auth URL** — URL отримання токена авторизації (напр. `https://auth-direct.КОД_ФИЛИИ.iot.grmu.com.ua`).
- **Логін** / **Пароль** — облікові дані доступу до DPD (пароль можна показати оком 👁).
- **Таймаут (сек)** — таймаут запиту, за замовчуванням `30`.

Збережіть кнопкою **«Зберегти»**.

> Якщо контейнери не резолвлять внутрішні DNS-імена DPD API — див. налаштування DNS у
> [deployment-docker.md](deployment-docker.md), розділ 7.

### 7.2 Завантаження промисловості з Excel — вкладка «Промисловість»

Перелік підприємств зручно завантажити пакетно через Excel-шаблон.

1. У верхній панелі натисніть **«↓ Шаблон»** — завантажиться порожній файл `enterprise_template.xlsx`
   з двома аркушами:
   - **«Дані»** — куди вносите підприємства (колонки: Підприємство, Серійний номер, Виробник,
     Модель коректора, Канал, Активний, Увімкнений, ID лінії).
   - **«Довідник»** — допоміжний аркуш зі **списком допустимих значень**: доступні **виробники**
     та **моделі коректорів**, а також **ID ліній** з їхніми обчислювачами та ЛУМГ.
2. Заповніть аркуш **«Дані»**, беручи значення **Виробник**, **Модель коректора** та **ID лінії**
   строго з аркуша **«Довідник»** (щоб вони збіглися з наявними в системі).
3. Угорі виберіть **«Відділення для імпорту»** (обов'язково — філіал, до якого належать записи).
4. Натисніть **«↑ Імпортувати»** і завантажте заповнений `.xlsx`.

> Кнопка **«↓ Експорт»** вивантажує поточні підприємства з БД (зручно, щоб доповнити наявний
> перелік, а не заповнювати з нуля).

> ⚠️ Імпорт — це **upsert (оновлення/додавання)**, а не повний перезапис: наявні записи
> оновлюються за ключем, нові — додаються. Записи, яких немає у файлі, у БД залишаються.
