# Налаштування GSM-опитування

## 1. Як це влаштовано

```
[Браузер] Опитування → підприємство → GSM → «Опитати»
     │  (кладе запит у картку опитування; сервер нікуди не дзвонить)
     ▼
[HLViewer, :8001] ◄── X-Agent-Key ── [ПК оператора: hlv-poller + GSM-модем]
     ▲                                        │  ATDP <номер>, CSD-дзвінок
     └──── години + доби ─────────────────────┘  коректор
```

Головне, що варто зрозуміти з першого разу: **сервер не має модема**. Кнопка
«Опитати» лише лишає запит у картці. Агент на машині оператора перепитує
сервер кожні 15 секунд, бачить запит, дзвонить і дорогою пише в журнал — те,
що видно на екрані як лог і смужка прогресу.

Звідси два наслідки:

- опитування «моментальне» рівно настільки, наскільки агент на зв'язку. Якщо
  жоден агент цієї картки не озивався останню хвилину, сервер відмовляє одразу:
  «Немає вільного модема: жоден агент не на зв'язку»;
- усі рішення приймає сервер: і розклад, і те, що вже прочитано.

## 2. Що потрібно мати

| | |
|---|---|
| Машина | Windows з COM- або USB-модемом. Агент — один .exe, Python не потрібен |
| Модем | GSM з підтримкою **CSD** (передача даних дзвінком), SIM з увімкненою послугою передачі даних |
| Мережа | доступ з цієї машини до HLViewer (`http://<сервер>:8001`) |
| Прилад | коректор із модемом, модель якого агент уміє читати; підприємство заведене в «Промисловості», коректор зазначено як встановлений |

Перелік моделей, які агент уміє читати, поповнюється. Перевіряти вручну нічого
не треба: якщо модель поки не підтримана, опитування відмовить одразу, ще до
дзвінка, і назве її — «Модель «…» модемом не опитується».

## 3. Агент і його ключ (Адміністрування → Опитування → Агенти)

Спершу ключ, бо програма на машині оператора попросить його при першому
запуску. Агент автентифікується **ключем**, а не сесією користувача: це
служба, а не людина в браузері.

1. «Агенти опитування» → «Додати».
2. **Назва** — так, щоб було зрозуміло, яка це машина і де вона стоїть:
   `Запоріжжя, каб. 214 (PC-ZP-214)`. Це єдине поле, за яким її потім
   упізнають у списках і в журналах.
3. **Філія** — обмежує видимість; «Усі філії», якщо машина обслуговує всі.
4. Зберегти. Одразу з'явиться жовта смуга з ключем.

**Ключ показується один раз.** У базі лежить лише його хеш, прочитати назад
його нізвідки. Загублений ключ не відновлюють — видають новий кнопкою «Новий
ключ», і старий тієї ж миті перестає працювати.

У колонці **«Стан»** видно, чи машина зараз на зв'язку: «на зв'язку» — агент
озивався останню хвилину, «офлайн · 12 хв» — скільки триває мовчанка, «ще не
виходив» — програму з цим ключем ще не запускали. Колонка **«Приладів»** — скільки
підприємств доручено цій машині в «Моніторі GSM».

## 4. Програма на машині оператора

На тій самій вкладці «Агенти», згори — кнопка **«Завантажити .exe»**. Один
файл, ~7 МБ; Python на тій машині не потрібен.

1. Скопіюйте файл на машину, де стоїть модем, у постійну теку —
   наприклад `C:\hlv-poller\`. Не в «Завантаження»: поруч із програмою
   з'явиться файл налаштувань, і тека має пережити прибирання диска.
2. Запустіть .exe. Перший запуск питає чотири речі:
   - **адресу сервера** — `http://10.145.174.62:8001`. Можна вписати й адресу,
     яку набирають у браузері (`http://10.145.174.62:3001`) — агент сам
     спробує `/api` під нею і запише те, що відповіло;
   - **ключ агента** — той, що показали в адмінці;
   - **порт модема** — програма спершу друкує порти цієї машини, лишається
     вибрати; порожній рядок бере перший зі списку;
   - **швидкість** — типово 9600.
3. Відповіді зберігаються в `agent.json` **поруч із .exe**, програма
   перевіряє ключ на сервері й одразу показує, що їй доручено. Далі вона
   просто чекає на завдання — вікно можна згорнути, але не закривати.

Другий і наступні запуски нічого не питають: є `agent.json` — працює.

## 5. Модем у картці підприємства (Адміністрування → Підприємства)

Номер телефону належить **підприємству**, а не коректору. Блок «Опитування
модемом» у картці підприємства:

- **Телефон** — український номер. Приймаються `050…`, `8050…`, `+38 (050) …`
  — зберігається завжди як `+380XXXXXXXXX`. Кнопка **«з ДПД»** у полі
  підставляє номер, який ДПД тримає для встановленого коректора. Якщо в ДПД
  номер не заповнений (лише `+380`), з'явиться підказка — впишіть номер вручну.
  Кнопка є лише в уже збереженому підприємстві.
- **Пароль приладу** — лише для ПК-В (Флоутек ТМ-2); типово `11`. Змінюйте, тільки якщо
  пароль змінено в самому коректорі.
- **Опитувати за графіком** — вмикає автоматичне опитування.
- **Години опитування** — список `ГГ:ХХ`. Порожньо означає загальні години
  (типово `08:00`).
- **Хто дзвонить** — машина (або машини) з модемом, якій доручено це
  підприємство.

Останній пункт обов'язковий. Номер без агента — це підприємство, яке
виглядає налаштованим і ніколи не опитується, тому поле підсвічується, поки
воно порожнє, а «Опитати» відмовляє словами «Цьому підприємству не призначено
жодного агента».

Кілька агентів означають **спільну чергу**, а не подвійний дзвінок: обидва
бачать той самий план, хто перший захопив картку — той і дзвонить, іншому
сервер відповідає «опитує інший агент», і той береться за наступне
підприємство свого списку. Захоплення знімається саме через 20 хвилин, тож
машина, вимкнена посеред сесії, нічого не блокує назавжди.

Щойно номер збережено, підприємство саме з'являється в «Моніторі GSM».
Окремо створювати картку опитування не треба — її більше ніде й не створюють
руками.

Модель коректора агент визначає сам під час дзвінка — вказувати протокол
ніде не треба. Якщо модель у картці не збігається з тією, що назвав прилад,
це видно в журналі дзвінка й у «Моніторі GSM» («відповів: …»), але
опитування триває. Читаються: КПЛГ, ВЕГА, Флоутек (ТМ-2 і ТМ-1, крім
варіанта ВР-1), Тандем (ТР і Т) та Універсал (01 і 02). Універсал-02 буває
дво­нитковим — яку нитку читати, агент бере з каналу приладу в картці ДПД.

### Журнал дзвінка

Кнопка журналу біля кожного рядка показує, що робив останній дзвінок. У тому
самому вікні є перемикач **«Технічний журнал»** — та сама розмова, але з
кожним кадром обміну, часом відповіді приладу й тим, що довелося відкинути з
лінії. Це для того, хто розбирає збій; оператору достатньо звичайного.

Обидва журнали зберігаються однаково: один файл на підприємство, який
переписує наступний дзвінок. Історії немає свідомо — несправність на лінії
повторюється щоразу однаково, а що саме сталося з кожною спробою, видно в
таблиці спроб.

## 6. Монітор GSM (Адміністрування → Опитування → Монітор GSM)

Ця вкладка — **монітор**, не редактор: тут нічого не налаштовується. Усі
налаштування, включно з тим, хто дзвонить, — у картці підприємства (розділ 5).
Тут видно стан усього парку на одному екрані.

| Колонка | Що показує |
|---|---|
| Підприємство | точка обліку; **назва клікається** — відкриває картку цього підприємства |
| Телефон | номер із картки |
| Коректор | № і модель того, що **зараз встановлено**; «немає встановлених» червоним, якщо всі зняті |
| Графік | години або «вручну» |
| Хто опитує | агенти, яким доручено цю картку; зелений — на зв'язку, сірий — офлайн, «нікому» помаранчевим |
| Останній опит | коли, скільки годин і діб, або код помилки |
| Стан | «очікує», «у черзі», смужка прогресу під час дзвінка, «без агента» |
| 🗒 | журнал останнього опитування цього підприємства |

Згори — **пошук** за назвою підприємства, заводським номером коректора або
номером телефону. Номер шукається цифрами, тож `067 537` і `+380675370320`
знаходять те саме.

Поруч три **фільтри**, у кожному можна вибрати кілька значень одразу:

- **Стан** — успішно, з помилкою, опитується зараз, у черзі, без агента,
  вимкнено, ще не опитували;
- **Як опитується** — за графіком чи тільки вручну;
- **Коректор** — моделі, з числом підприємств біля кожної.

У списках стану й моделей показані тільки ті значення, що є на цьому екрані.

**Журнал** (кнопка в кінці рядка) показує лог останнього опитування цього
підприємства: кого набирали, що відповів прилад, скільки прочитано — і чим
усе скінчилося.

Той самий файл читає й екран опитування, поки триває дзвінок, — інших копій
журналу немає. Файли лежать на сервері в теці `logs/poll`, по одному на
підприємство (`enterprise-<id>.log`), кожна нова сесія переписує свій. Назва
файлу — за id, тож перейменування підприємства журнал не губить. Теку можна
перенести змінною `POLL_LOG_DIR` у `.env`, але типово вона вже така.

«Нікому» в колонці «Хто опитує» підсвічується свідомо: підприємство, якого не
взяв жоден агент, ніколи не опитується, а на всіх інших колонках виглядає
точно як справне. Виправляється це в картці підприємства — назва в першій
колонці її й відкриває.

## 7. Запуск агента

Звичайний режим — чекати на завдання; після першого налаштування агент
нічого не питає:

```
  Агент опитування HLViewer 0.1.0
  Налаштування: C:\hlv-poller\agent.json
  Сервер: http://10.145.174.62:8001
  Порт:   COM5 @ 9600

  Сервер на зв'язку. Доручено приладів: 1
    Запорізький асфальтобетонний завод  №22038  +380675370320

  Чекаю на завдання, PC-ZP-214 (Windows), порт COM5 @ 9600
```

Агент сам переживає перезапуск сервера й обрив мережі: недоступний сервер для
нього — це очікування, а не зупинка. А от закрите вікно означає, що машина
нікому не відповідає — на екрані опитування це виглядає як «немає вільного
модема». Тому там, де опитують за графіком, агента роблять службою (наступний
розділ).

## 8. Служба: щоб опитування працювало без відкритого вікна

Спершу дві речі, які інакше зіпсують будь-який зі способів:

1. **Тека агента має бути локальною.** `C:\hlv-poller\` — не «Робочий стіл» і не
   тека OneDrive: служба працює від системного облікового запису, у якого
   вашого OneDrive просто немає, і `agent.json` вона не знайде.
2. **Обов'язково аргумент `run`.** Без нього програма чекає на Enter у вікні,
   якого ніхто не бачить, і служба «висить» без жодної роботи.

### Спосіб 1 — Планувальник завдань (нічого ставити не треба)

```bat
schtasks /create /tn "HLViewer GSM agent" /sc onstart /ru SYSTEM /rl HIGHEST ^
  /tr "C:\hlv-poller\hlv-poller-0.1.0.exe run --log C:\hlv-poller\agent.log"
```

Те саме через вікно: «Створити завдання» → «Виконувати незалежно від того, чи
ввійшов користувач» → «Запускати з найвищими правами» → тригер «При запуску
комп'ютера» → дія: програма `hlv-poller-0.1.0.exe`, аргументи
`run --log C:\hlv-poller\agent.log`, «Почати в» — `C:\hlv-poller`.

Запустити зараз, не перезавантажуючись: `schtasks /run /tn "HLViewer GSM agent"`.
Зупинити: `schtasks /end /tn "HLViewer GSM agent"`. Видалити:
`schtasks /delete /tn "HLViewer GSM agent" /f`.

Планувальник **не перезапускає** програму, якщо вона впала — тому на вкладці
«Параметри» варто увімкнути «Перезапускати кожні 1 хв» (до 3 разів).

### Спосіб 2 — NSSM (справжня служба з автоперезапуском)

[NSSM](https://nssm.cc) — одна програма, яка робить службу з будь-якого .exe і
сама піднімає її після збою:

```bat
nssm install HlvPoller C:\hlv-poller\hlv-poller-0.1.0.exe run
nssm set HlvPoller AppDirectory C:\hlv-poller
nssm set HlvPoller AppStdout C:\hlv-poller\agent.log
nssm set HlvPoller AppStderr C:\hlv-poller\agent.log
nssm set HlvPoller Start SERVICE_AUTO_START
nssm start HlvPoller
```

Далі — як зі звичайною службою: `nssm stop HlvPoller`, `nssm restart HlvPoller`,
`nssm remove HlvPoller confirm`. Журнал тут пише сам NSSM, тож `--log` не
потрібен.

### Чим `sc create` не годиться

```bat
sc create HlvPoller binPath= "C:\hlv-poller\hlv-poller-0.1.0.exe run"
```

Так робити не варто: це звичайна консольна програма, а не служба Windows. Вона
запуститься й одразу отримає «помилка 1053: служба не відповіла на запит
вчасно», бо не вміє відповідати диспетчеру служб. Саме цю роботу за неї й
робить NSSM.

### Що агент робить у журналі

`--log` дублює у файл те саме, що видно у вікні (файл ротується на 1 МБ, два
попередніх зберігаються):

```
12.09 17:15:40  Чекаю на завдання, PC-ZP-214 (Windows), порт COM5 @ 9600
12.09 17:15:40  Сервер недоступний: Невідомий або вимкнений ключ агента
```

Це журнал **машини**: чи бачить вона сервер, чи прийнято ключ, чи відкривається
порт. Журнал конкретного дзвінка дивляться не тут, а в «Моніторі GSM» — кнопка
журналу в рядку підприємства.

### Перевірка, що служба справді працює

«Адміністрування → Опитування → Агенти»: стан цієї машини має бути **«на
зв'язку»** (агент озивається кожні 15 секунд). Якщо там «офлайн» — дивіться в
`agent.log`: майже завжди це або не та тека (не знайдено `agent.json`), або
ключ від видаленого агента.

### Кілька модемів на одній машині

Один запущений агент працює з **одним** COM-портом — так у `agent.json`. Щоб
задіяти два модеми, запустіть два агенти:

1. заведіть у адмінці **другий** агент — зі своїм ключем;
2. покладіть програму в окрему теку з власним `agent.json`, де свій ключ і
   свій порт (або запускайте з `--config <шлях>`);
3. у моніторі GSM призначте кожному агентові підприємства.

Призначати можна як завгодно — це і є те місце, де ви вирішуєте, як ділити
роботу між модемами.

**Різні підприємства кожному.** Звичний поділ: кожен модем має свій перелік.
Зрозуміло, хто кого дзвонить, легко читати журнали. Мінус один: якщо агент
вимкнений, його підприємства ніхто не опитає.

**Ті самі підприємства обом.** Теж можна, і тоді черга ділиться сама:
обидва агенти беруть той самий список, сервер віддає підприємство тому, хто
попросив першим, другий пропускає й бере наступне. Виходить вирівнювання за
фактичною зайнятістю модема, а зупинка одного ПК нічого не спиняє.

Одне й друге можна поєднувати: більшість розкидати по модемах, а важливі
підприємства призначити обом — щоб їх опитали в будь-якому разі.

Ключі мають бути **різні**. Два процеси з одним ключем сервер вважає одним
агентом — вони перебиватимуть одне одному ознаку «на зв'язку».

## 9. Опитування з браузера (розділ «Опитування»)

Підприємство → дві вкладки, і це дві різні дії:

- **Опитування** — сходити по дані та покласти їх у базу;
- **Архів** — показати те, що вже в базі (дати обираються тут).

На вкладці «Опитування» — перемикач джерела:

- **Сервер Радміртех** — ДПД по інтернету. Діапазон обирає сервер: **від
  найсвіжішого запису цього підприємства до завтра**, а якщо в базі порожньо
  — **від 01.01.2024**. Завтра — бо доба газова, і години поточної підписані
  датою, яка ще не настала. Пише, скільки записів із прочитаних виявилися
  **новими**, а не скільки їх було всього.
- **GSM** — доступний лише тим підприємствам, де є номер. Дзвінок іде негайно,
  якщо є вільний агент.

Опитування завжди бере **обидва архіви — годинний і добовий**. Розділяти їх
немає сенсу: доба закривається за контрактною годиною (07:00), тож «нових діб
немає» при свіжих годинах — нормальний стан, а не збій.

Під час GSM-опитування на екрані видно те саме, що бачила б людина біля
модема: ініціалізація, «Набираю», спроба 1 з 3, «З'єднання за 22 300 мс»,
заводський номер, скільки записів треба прочитати, смужка прогресу.

Перед читанням агент звіряє **заводський номер**: якщо озвався не той
коректор, що значиться встановленим, опитування зупиняється з поясненням.
Це або заміна, якої ніхто не записав, або дзвінок не туди — зберігати такі
показання нікуди.

Скільки читається за раз: перше опитування бере повне кільце (до 720 годин і
127 діб — це хвилини на лінії), далі лише те, що з'явилося **після
найсвіжішого записаного** — тобто «дочитати з того місця, де спинилися».

### Зупинити опитування

Поки дзвінок триває, поруч зі станом є **«Зупинити»**. Дві різні речі під
однією кнопкою:

- запит, якого агент ще не взяв, просто знімається — не сталося нічого;
- дзвінок, що вже йде, звідси зупинити не можна: модем на іншій машині. Тому
  піднімається прапорець, агент бачить його з наступним звітом (секунда-дві) і
  кладе слухавку **між записами**, а не посеред читання.

Прочитане цим дзвінком **відкидається** — так само, як при обриві порту, і з
тієї ж причини: покриття рахується від найновішого збереженого запису, тож
три години з одинадцяти поховали б вісім проміжних. Дані нікуди не зникають —
вони лишаються в коректорі, і їх прочитає наступний опит. Скасований дзвінок
коштує лише тих хвилин, що встиг протривати.


## 10. За графіком

Картка з увімкненим «Опитувати за графіком» опитується сама: агент кожні 15
секунд питає сервер, що доручено цій машині, і сервер відповідає, кого пора.
Ручний запит завжди йде поза чергою — і навіть тоді, коли графік вимкнено:
вимкнений графік означає «не за розкладом», а не «не читати». Але це **один
дзвінок, а не постійне доручення**: запит знімається після сесії з будь-яким
результатом. Не вдалося — помилка видна на екрані, а чи набирати ще раз,
вирішує людина.

**Що буде після невдалого дзвінка.** Невдача не рахується опитуванням —
«останній опит» зсуває тільки успіх, — тому агент спробує ще, але **не більше
трьох разів на одну заплановану годину і не частіше ніж раз на 15 хвилин**. Не
вийшло тричі — підприємство лишають у спокої до наступного часу з графіка.

Ручні дзвінки не витрачають ті три спроби — рахуються тільки планові.

Порядок черги визначає сервер: спершу ручні запити, далі пріоритет, далі той,
кого опитували найдавніше.

**Коли підприємств багато.** Модем один, дзвінки йдуть по черзі, тож час
черги складається. Заміряно на живих дзвінках:

| | Набір | Читання доби | Разом |
|---|---|---|---|
| КПЛГ | ~30 с | ~30 с | **~1 хв** |
| ВЕГА | ~30 с | ~2 хв | **~2,5 хв** |

ВЕГА дорожча, бо її протокол віддає один запис на кадр, а КПЛГ — сторінку з
восьми годин.

Тридцять підприємств на одну годину — це, отже, від півгодини до години
безперервних дзвінків. Розкладу це не ламає: підприємство, до якого черга
дійшла о 21:10, усе одно закриває слот 20:15. Але останні в черзі читаються
на годину пізніше, ніж написано, і якщо поставити такий парк на **щогодинне**
опитування, черга не встигне розсмоктатись до наступного слоту.

Тому години краще рознести: не тридцять карток на 20:15, а по вісім-десять на
20:00, 20:30, 21:00.

## 11. Діагностика з командного рядка

```bat
hlv-poller ports              # COM-порти цієї машини
hlv-poller plan               # що доручено цій машині і кого пора опитати
hlv-poller devices 3 4        # призначити машині прилади (те саме, що в моніторі)
hlv-poller poll 3             # додзвонитися й опитати один прилад просто зараз
hlv-poller --debug poll 3     # те саме, з кожним кадром обміну
hlv-poller probe-arch 3 1 5 6 # діагностика: прочитати архів за індексами
hlv-poller run --once         # один прохід замість очікування
hlv-poller --log agent.log run # звичайний режим із журналом у файл
```

## 12. Що означають помилки

| Код / текст | Що сталося |
|---|---|
| `no_modem` — модем не відповідає | немає зв'язку з самим модемом: живлення, кабель, не той COM-порт |
| `no_dialtone` — немає лінії | модем є, лінії немає: SIM, антена, баланс |
| `no_answer` / `busy` | прилад не бере слухавку або вже на іншому дзвінку |
| `no_carrier` — немає носійної | з'єднання не встановилося: найчастіше не той номер, або на тому кінці не модем |
| `timeout` | з'єднання не встигло встановитися за відведений час |
| `wrong_serial` | озвався коректор з іншим заводським номером — опитування зупинено |
| `wrong_model` | додзвонилися, але прилад не відповідає протоколом моделі, вказаної в картці — найчастіше в картці не та модель коректора |
| `vega` — прилад не показав архів | прилад назвався, але архів не читається: адреса, швидкість або режим налаштування |
| `no_reader` | модель не з тих, що ми вміємо читати по GSM |
| `not_stored` | прочитали, але сервер не прийняв — опитування вважається невдалим, бо дані нікуди не лягли |
| `cancelled` — зупинено на вимогу | хтось натиснув «Зупинити». Не помилка приладу; прочитане відкинуто навмисно — див. «Зупинити опитування» |
| `link_lost` — порт зник посеред сеансу | зник не прилад, а сам COM-порт: USB-модем відпав від шини. Прочитане цим дзвінком відкидається; перевірте кабель, хаб і живлення порту |
| «Немає встановлених корректорів» | у картці підприємства всі коректори зняті — дзвонити нема по що |
| `refused` — прилад відмовив у читанні архіву | найімовірніше, не той пароль у картці підприємства |
| «Не призначено жодного агента» | у картці підприємства порожнє поле «Хто дзвонить» |
| «Агент … не на зв'язку» | машину названо, але програма на ній не запущена |
